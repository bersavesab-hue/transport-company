# 存档版本与迁移

## 基本规则

1. `saveVersion` 是整数，只在存档结构变化时增加。
2. `gameVersion` 是发布版本，不代替 `saveVersion`。
3. 每次迁移只负责相邻版本，例如 `1 -> 2`。
4. 跨版本升级依次执行所有迁移。
5. 迁移前创建备份，迁移后执行完整校验。
6. 迁移失败时保留原档，不覆盖。

## 初始版本

`saveVersion: 1`

必须包含：

- 当前游戏时间与时间速度。
- 已启用功能开关。
- 已安装内容包及版本。
- 公司现金、债务和设施。
- 车辆实例及动态状态。
- 订单实例及状态。
- 当前路线和运输进度。
- 财务流水摘要。
- 随机种子。
- 已执行迁移记录。

## 迁移登记

迁移器使用以下命名：

- `migrateSaveV1ToV2`
- `migrateSaveV2ToV3`

禁止写一个无法追踪来源的“升级到最新版”大函数。

### 已执行迁移

| 迁移 | 新增状态 | 保留内容 |
| --- | --- | --- |
| `1 -> 2` | 六小时市场周期、当前市场事件 | 现金、车辆、订单、运输进度和经营历史全部保留 |
| `2 -> 3` | 停车位、车辆资产账、逐车贷款、二手车源与永久流水编号 | 原有现金、总债务、车辆位置、装载订单、在途运输和事件历史全部保留 |

迁移记录编号：`save_v1_to_v2_dynamic_market`、`save_v2_to_v3_fleet_assets`。同一存档重复加载不会重复执行。

## 内容缺失处理

如果存档引用的内容包暂时缺失：

- 不删除相关车辆、城市或订单。
- 把对应实例标记为冻结。
- 禁止继续参与经济结算。
- 内容包恢复后重新激活。

如果内容已经正式下架：

- 通过迁移规则转换为明确替代内容。
- 记录转换日志。
- 对资产价值差额进行一次性财务调整。

## 验收条件

- 新版本可以读取所有正式发布过的存档版本。
- 迁移同一存档两次不会重复发放资产或重复扣款。
- 迁移前后总资产变化必须有日志解释。
- 任何失败不会覆盖唯一原始存档。
