# 系统架构

## 分层

### 规则核心层

纯 TypeScript 规则，不接触页面、图片、平台 API 或本地文件。

包含：时间、地图、城市、市场、订单、运输单位、路线、财务、公司、NPC 公司、事件、执照与存档状态。

### 应用层

接收玩家命令，调用规则核心，组织一次完整用例，例如“承接订单”“分配车辆”“开始路线”“购买车辆”。

### 数据适配层

读取内容包、校验数据、加载存档、写入存档。适配层只能提供数据，不能改变规则结果。

### 表现层

地图、车辆动画、卡片、抽屉、弹窗、音效和触摸操作。表现层根据事件更新，不持有权威游戏状态。

## 十二个模块

| 模块 | 权威状态 | 对外能力 |
| --- | --- | --- |
| 时间 | 当前游戏秒、速度、日历 | 暂停、推进、排程 |
| 地图 | 节点、连接、路网状态 | 寻路、距离、通行验证 |
| 城市 | 产业、需求、容量 | 生成供需因子 |
| 市场 | 运价、供需、饱和度 | 报价、刷新订单 |
| 订单 | 委托、合同、状态 | 接受、取消、交付 |
| 运输单位 | 运力、车况、里程、人员 | 装载、出发、维护 |
| 路线 | 停靠点、分段、载荷 | 规划、重算、统计空驶 |
| 财务 | 现金、债务、应收应付 | 记账、结算、预算验证 |
| 公司 | 资产、设施、人员、资质 | 扩张、雇佣、采购 |
| NPC 公司 | 策略、资产、市场行为 | 竞价、扩张、退出 |
| 事件 | 条件、效果、持续时间 | 触发、选择、结束 |
| 存档迁移 | 版本、迁移记录 | 升级、校验、回滚备份 |

## 命令与事件

界面只能提交命令：

- `AcceptOrder`
- `AssignTransportUnit`
- `PlanRoute`
- `StartTrip`
- `ResolveIncident`
- `PurchaseVehicle`
- `MaintainVehicle`

规则核心验证后产生领域事件：

- `OrderAccepted`
- `CargoLoaded`
- `TripStarted`
- `SegmentCompleted`
- `IncidentTriggered`
- `DeliveryCompleted`
- `LedgerEntryPosted`

所有财务和状态修改都必须能追溯到领域事件。

## 多运输方式扩展

所有运输单位实现统一 `TransportModeAdapter`。订单、财务、合同和公司系统只认识公共运力、路网、站点和成本接口。

运输方式差异由适配器提供：

- 公路：司机工时、道路拥堵、收费和灵活停靠。
- 客运：座位、班次、上座率和投诉。
- 铁路：编组、时刻槽和车站中转。
- 航运：船期、港口箱位和天气窗口。
- 航空：航班时刻、机场容量和高时效货物。

## 功能开关

未完成模块通过功能开关保持关闭。存档仍记录开关版本，禁止用未完成数据影响正式经济。

初始开关：

- `roadFreight`: 开启
- `dynamicMarket`: 开启
- `smartDispatch`: 开启
- `cityIntelligence`: 开启
- `fleetExpansion`: 开启
- `roadPassenger`: 数据接口开启、正式运营关闭
- `rail`: 关闭
- `shipping`: 关闭
- `aviation`: 关闭
- `internationalMap`: 关闭
- `npcCompetition`: 关闭
- `dealership`: 开启
- `usedVehicleMarket`: 开启

## 性能边界

- 权威模拟使用固定步长，不跟随屏幕帧率。
- 地图只更新视口内图标；离屏车辆采用低频模拟。
- 城市标签按缩放级别加载。
- 市场订单按城市分区生成，不在每帧全量计算。
- 存档采用稳定编号引用，不复制整份静态内容数据。
